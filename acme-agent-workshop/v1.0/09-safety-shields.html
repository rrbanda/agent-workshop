Module 09: Safety Shields

Learning Objectives

  • Register safety shields with Llama Stack

  • Test content safety directly via the safety API

  • Integrate input and output shields into agents

Capstone Preview: In the capstone, you will wrap the mortgage agent with these safety shields to block social-engineering attempts like "How can I forge bank statements?"

Prerequisites

  • Module 03: Llama Stack Basics completed

  • A safety provider available on your Llama Stack server (the default trustyai_fms is pre-configured)

Concepts

Safety shields are content classifiers that sit between the user and the LLM. An input shield scans the user’s message before it reaches the model. An output shield scans the model’s response before it reaches the user. In Llama Stack, shields are registered once and can be attached to any agent.

This workshop uses the TrustyAI Guardrails Orchestrator (trustyai_fms provider), which provides regex-based PII detectors that catch personally identifiable information such as email addresses, Social Security numbers, and credit card numbers. When PII is detected, the shield returns a violation that blocks the content.

If your Llama Stack server has a llama-guard provider instead, set SHIELD_PROVIDER=llama-guard and SHIELD_MODEL=<your-model> in .env. Llama Guard uses an LLM to classify content as safe or unsafe across broader harm categories (violence, fraud, etc.) rather than regex PII detection.

Step-by-Step

Working directory: All commands in this module run from 09-safety-shields/.
Services needed: Llama Stack server with a safety provider (default: trustyai_fms).

1. Explore Available Providers (Optional)

Before registering a shield, you can explore what your Llama Stack server has available:

python 1_list_models.py
python 2_list_safety_providers.py
python 3_list_shields.py

Script 2 lists safety providers — verify that trustyai_fms (or your configured SHIELD_PROVIDER) appears in the output. If it does not, contact your workshop administrator.

2. Register a Shield

python 4_register_shield.py

3. Test the Shield

python 5_test_shield.py

Expected: clean content passes; messages containing PII (email, SSN, credit card) are flagged as violations.

4. Agent with Shields

python 6_agent_shield.py

The agent blocks inputs containing PII and filters unsafe outputs.

What You Should See

Shield Test (script 5)

Testing shield: pii_detector

Test: Clean content (should PASS)
  Input: "What is the weather like today?"
  Result: SAFE - Content passed safety checks

Test: Contains email (should VIOLATE)
  Input: "My email is test@example.com"
  Result: VIOLATION DETECTED

Test: Contains SSN (should VIOLATE)
  Input: "My SSN is 123-45-6789"
  Result: VIOLATION DETECTED

Test: Contains credit card (should VIOLATE)
  Input: "Card number: 4111-1111-1111-1111"
  Result: VIOLATION DETECTED

User: Give me a sentence that contains the word: aloha

Troubleshooting

Problem Solution

"Shield not found"

Verify SHIELD_ID matches a registered shield on your Llama Stack server (run 3_list_shields.py to check)

All inputs flagged as violations

Check that SHIELD_ID matches the registered shield name

No safety providers listed

Your Llama Stack config may need a safety provider — check the server config

Key Takeaways

  • Shields provide content safety guardrails for LLM agents

  • client.safety.run_shield() checks messages before and after agent turns

  • Shields are pluggable — swap between TrustyAI (regex PII) and Llama Guard (LLM classification) by changing SHIELD_PROVIDER in .env

  • Shields are registered once and can be attached to any agent

Presenter Walkthrough

A talk-through guide for presenting the workshop without running code live. Each section shows what the module teaches, the key code, and the actual output.

Overview: What Are We Building?

We’re building AI agents using Llama Stack — an open-source platform that gives you a single, unified API for agents, inference, tools, RAG, safety, and evaluations.

The agents serve ACME Financial Services, a fictional company with customer data, financial records, and a mortgage lending operation.

Model

We use Gemini 2.5 Flash through the Llama Stack server — demonstrating that Llama Stack is model-agnostic. You write your code once, swap the model via an environment variable.

Module 03 — Hello World Agent

What it teaches: The absolute basics — create a client, create an agent, ask a question, get an answer. The "Hello World" of agentic AI.

Key Code

from llama_stack_client import LlamaStackClient, Agent

# Connect to the server
client = LlamaStackClient(base_url=LLAMA_STACK_BASE_URL)

# Create an agent with instructions
agent = Agent(
    client,
    model=INFERENCE_MODEL,
    instructions="You are a helpful assistant.",
)

# Start a conversation
session_id = agent.create_session(session_name="hello_world")

# Ask a question
response = agent.create_turn(
    session_id=session_id,
    messages=[{"role": "user", "content": "Explain what an AI agent is in one sentence."}],
    stream=False,
)

print(response.output[0].content[0].text)

Actual Output

Base URL: https://llamastack-llamastack.apps.ocp.v7hjl.sandbox2288.opentlc.com
Model:    gemini/models/gemini-2.5-flash
An AI agent is an autonomous entity that perceives its environment, makes
decisions, and performs actions to achieve specific goals.

Talking Points

  • 3 objects: LlamaStackClient (connection), Agent (brain), Session (conversation)

  • 4 lines of actual logic — everything else is boilerplate

  • The instructions parameter is the system prompt — tells the agent who it is

  • stream=False gives you the complete response; stream=True gives you token-by-token

Module 04 — Agents with Tools (MCP)

What it teaches: How to give agents real capabilities by connecting them to backend APIs through the Model Context Protocol (MCP). The agent decides which tools to call and chains them together.

The MCP Concept

User: "Find Thomas Hardy's orders"

Agent thinks → "I need to find the customer first"
  → calls search_customers("Thomas Hardy")
  → gets back customer ID "AROUT"

Agent thinks → "Now I can look up their orders"
  → calls fetch_order_history("AROUT")
  → gets back 3 orders

Agent → formats and presents the answer

Key Code

# Define which MCP servers the agent can use
mcp_tools = [
    {
        "type": "mcp",
        "server_url": CUSTOMER_MCP_SERVER_URL,   # Customer lookup tools
        "server_label": "customer",
    },
    {
        "type": "mcp",
        "server_url": FINANCE_MCP_SERVER_URL,     # Order/invoice tools
        "server_label": "finance",
    }
]

# Create a multi-domain agent
agent = Agent(
    client,
    model=INFERENCE_MODEL,
    instructions="When given a name, first look up the customer "
                 "to get their ID, then use that ID to retrieve their orders.",
    tools=mcp_tools,
)

Actual Output

Base URL:     https://llamastack-llamastack.apps.ocp.v7hjl.sandbox2288.opentlc.com
Model:        gemini/models/gemini-2.5-flash
Customer MCP: https://mcp-customer-route-acme-workshop.../mcp
Finance MCP:  https://mcp-finance-route-acme-workshop.../mcp

* Order Number: ORD-003, Total Amount: 89.99, Status: PENDING

Talking Points

  • MCP = the USB-C of AI tools — a standard protocol so any LLM can call any backend

  • The agent autonomously decides which tools to call and in what order

  • Cross-domain reasoning: the agent chains Customer API → Finance API without being told how

  • The MCP servers are simple Python wrappers (FastMCP) around existing REST APIs

  • You don’t modify your existing APIs — you just wrap them

Module 05 — Multi-Turn Conversations

What it teaches: Agents remember context across conversation turns. Ask about a person, then say "what are their orders" — the agent knows who "their" refers to.

Key Code

# Same session for both turns -- that's the magic
session_id = agent.create_session(session_name="multi_turn_session")

# Turn 1: Who is Thomas Hardy?
agent.create_turn(
    messages=[{"role": "user", "content": "who does Thomas Hardy work for?"}],
    session_id=session_id,   # ← same session
)

# Turn 2: Pronoun resolution -- "their" = Thomas Hardy's company
agent.create_turn(
    messages=[{"role": "user", "content": "what are their orders?"}],
    session_id=session_id,   # ← same session, context preserved
)

Actual Output

============================================================

Module 08 — RAG (Retrieval-Augmented Generation)

What it teaches: How to give agents access to your private documents (HR policies, lending rules, etc.) using vector stores and the file_search tool.

The RAG Flow

1. Upload document → Llama Stack chunks it (100 tokens, 10 overlap)
2. Each chunk → embedding model → vector store (hybrid: BM25 + semantic)
3. User asks a question
4. Agent calls file_search → vector store returns top-5 relevant chunks
5. Agent reads chunks → synthesizes answer with citations

Key Code

# Create agent with file_search tool pointing to vector store
agent = Agent(
    client,
    model=INFERENCE_MODEL,
    instructions="You MUST use the file_search tool to answer ALL questions.",
    tools=[
        {
            "type": "file_search",
            "vector_store_ids": [vector_store.id],
        }
    ],
)

Actual Output

Query: What do I receive when I retire?
--------------------------------------------------------------------------------
🤔

🔧 Executing file_search (server-side)...
🤔 When you retire, you receive a life-sized statue of yourself crafted from
Belgian chocolate or artisanal vegan carob, a lifetime supply of your chosen
treat, and a personal bard to sing your praises at inconvenient moments.
The "Midas Touch & Beyond" Retirement Plan also offers a 401(k) where
contributions are multiplied based on astrological alignment.

Talking Points

  • The HR benefits document is intentionally absurd — chocolate statues and personal bards — so you can clearly see the agent is reading from the document, not making things up

  • Hybrid search (BM25 + semantic) catches both keyword matches and meaning matches

  • The file_search tool is server-side — the Llama Stack server handles the retrieval

  • Same pattern applies to any document: legal contracts, product manuals, lending policies

Module 09 — Safety Shields

What it teaches: How to protect agents from processing sensitive data using safety shields. We use TrustyAI Guardrails with regex-based PII detectors for email, SSN, and credit card numbers.

Key Code

# Run content through a shield
response = client.safety.run_shield(
    shield_id="pii_detector",
    messages=[{"role": "user", "content": "My SSN is 123-45-6789"}],
)

if response.violation:
    print(f"VIOLATION: {response.violation.user_message}")
else:
    print("SAFE")

Actual Output

Testing shield: pii_detector

Test: Clean content (should PASS)
  Input: "What is the weather like today?"
  Result: SAFE

Test: Contains email (should VIOLATE)
  Input: "My email is test@example.com"
  Result: VIOLATION DETECTED

Test: Contains SSN (should VIOLATE)
  Input: "My SSN is 123-45-6789"
  Result: VIOLATION DETECTED

Test: Contains credit card (should VIOLATE)
  Input: "Card number: 4111-1111-1111-1111"
  Result: VIOLATION DETECTED

All 4 tests completed successfully

Talking Points

  • Shields are composable — wrap any agent with run_shield() before/after each turn

  • Input shields catch PII before it reaches the model

  • Output shields catch the model from leaking sensitive data

  • This is a guardrail pattern — the shield tells you what was detected and why

  • In production you’d combine regex PII + content safety (harassment, fraud, etc.)

Module 10 — Evaluations

What it teaches: How to systematically test whether your agents give correct answers using eval datasets, scoring functions, and LLM-as-judge.

The Eval Pattern

1. Register a dataset of questions + expected answers
2. Define a scoring function (e.g., subset_of)
3. Create a benchmark combining dataset + scoring
4. Run the benchmark against the model
5. Review results

Actual Output

Using model: gemini/models/gemini-2.5-flash

Question: Sally's mother has 4 children: Spring, Summer, Fall, and ____.
          What is the fourth child's name?
Answer:   The fourth child's name is Sally. ✓

Question: A farmer has 17 sheep. All but 9 run away.
          How many sheep does the farmer have left?
Answer:   The farmer has 9 sheep left. ✓

Question: A bat and a ball cost $1.10 in total. The bat costs $1.00 more
          than the ball. How much does the ball cost?
Answer:   The ball costs $0.05. ✓

Accuracy: 3/3 (100%)

Talking Points

  • These "trick questions" are great for showing model reasoning quality

  • Scoring is automated — no manual review needed for pass/fail

  • LLM-as-judge uses one model to evaluate another’s output (useful when answers aren’t exact matches)

  • This is how you catch regressions when you change models, prompts, or RAG configurations

Capstone — Mortgage Approval Agent

The scenario: Build an AI underwriting assistant for ACME’s mortgage division. The agent automates the conditional approval loop — the most delay-prone step in mortgage processing.

The Conditional Approval Loop

Conditional Approval Issued
    → Agent identifies missing documents
    → Agent notifies borrower ("Please submit W-2")
    → Borrower uploads document
    → Agent looks up policy rules via RAG
    → Agent reviews document against policy
    → Accept or Reject?
        → ACCEPTED: mark condition SATISFIED
        → REJECTED: notify borrower with reason, loop back
    → All conditions satisfied?
        → Yes: Clear to Close!
        → No: continue loop

What the Agent Uses

Capability How It’s Used

Tools (Module 04)

Look up applications, documents, conditions, credit reports

RAG (Module 08)

Search the lending policy for acceptance criteria

Multi-Turn (Module 05)

Remember context across the review process

Safety (Module 09)

Shield inputs/outputs for PII

Evals (Module 10)

Score agent answers against expected results

  • Each turn uses multiple capabilities: tools + RAG + conversation memory

  • Turn 3 demonstrates cross-referencing: agent checks the uploaded document date against the policy rule retrieved via RAG

  • Turn 4 shows the agent taking action: sending a notification to the borrower

  • This is a realistic enterprise workflow — the agent replaces manual back-and-forth that typically takes days

Key Takeaway

The pattern is always the same:

# 1. Connect
client = LlamaStackClient(base_url=...)

# 2. Create an agent with capabilities

# 3. Start a conversation
session_id = agent.create_session(...)

# 4. Ask questions
response = agent.create_turn(messages=[...], session_id=..., stream=True)

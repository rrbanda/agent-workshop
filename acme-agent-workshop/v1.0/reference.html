Environment Variables

All modules share a single .env file at the repo root. Copy .env.example to .env and update values for your deployment scenario. See .env.example for the full annotated template.

In an instructor-led workshop, your instructor provides the remote URLs for Llama Stack, APIs, and MCP servers. Uncomment the "Remote" lines in .env.example and replace the placeholder URLs.

Troubleshooting

Problem Solution

RuntimeError: No response available

Verify MCP servers are deployed on OpenShift and routes are reachable. Check CUSTOMER_MCP_SERVER_URL and FINANCE_MCP_SERVER_URL in your .env.

Connection refused on Llama Stack

Verify the server is running: curl $LLAMA_STACK_BASE_URL/v1/models

LLAMA_STACK_BASE_URL not set

Copy .env.example to .env and set LLAMA_STACK_BASE_URL to the pre-deployed RHOAI server URL

Empty tool lists

Verify MCP servers are deployed on OpenShift (oc get pods -l app=customer-mcp) and registered with Llama Stack (Module 02, step 6).

MCP tools fail

MCP server URLs must be reachable from the Llama Stack server. Both run on OpenShift, so use the route URLs from oc get routes.

Model not found

Check INFERENCE_MODEL matches a model on your Llama Stack server (curl $LLAMA_STACK_BASE_URL/v1/models)

429 Too Many Requests or rate limiting

The MaaS inference backend has rate limits. Wait 30-60 seconds and retry. For eval scripts, the built-in retry logic handles this automatically.

"already exists" on oc new-build

The build config already exists. Skip oc new-build and just re-run oc start-build.

oc command not found

Install the OpenShift CLI from mirror.openshift.com

Import errors

Activate your venv and run pip install -r requirements.txt

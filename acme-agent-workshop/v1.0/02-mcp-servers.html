Module 02: MCP Servers

Learning Objectives

  • Understand the Model Context Protocol (MCP)

  • Write FastMCP tool wrappers for REST APIs

  • Deploy MCP servers on OpenShift with routes

  • Register MCP servers with Llama Stack

  • Test MCP tools independently

Capstone Preview: In the capstone, a Mortgage MCP server wraps the Mortgage API using the same FastMCP pattern you learn here — same @mcp.tool() decorators, same httpx calls, same structure.

Prerequisites

  • Module 01: Backend APIs deployed (locally or on OpenShift)

  • Module 00: Environment Setup completed

Concepts

The Model Context Protocol (MCP) provides a standard way to expose tools to LLMs. An MCP server wraps existing APIs as tool functions that an LLM can discover and call. FastMCP is a Python library that makes building MCP servers straightforward.

MCP servers must be reachable from the Llama Stack server. If your Llama Stack runs on OpenShift (remote), MCP servers must also be deployed remotely. MCP servers on localhost are invisible to a remote Llama Stack — you will get RuntimeError: No response available. See Deployment Scenarios.

ACME MCP Tools

Customer MCP

Tool Wraps Description

search_customers

GET /api/customers

Search by company name, contact name, email, or phone

get_customer

GET /api/customers/{id}

Get a specific customer by ID

Finance MCP

Tool Wraps Description

fetch_order_history

POST /api/finance/orders/history

Get orders for a customer

fetch_invoice_history

POST /api/finance/invoices/history

Get invoices for a customer

Read the Code

Before deploying, review how an MCP server wraps a REST API. Open 02-mcp-servers/customer-mcp/customer-api-mcp-server.py:

  • FastMCP("customer-api") creates the server

  • @mcp.tool() decorates async functions that call the backend API via httpx

  • mcp.run(transport="http", port=…​, host=…​) starts the HTTP transport

  • Environment variables configure the backend API URL and port

The finance MCP server (02-mcp-servers/finance-mcp/finance-api-mcp-server.py) follows the same pattern.

Step-by-Step

Choose the deployment path that matches your setup:

Option A: Deploy MCP Servers on OpenShift (Recommended)

This is the recommended path when your Llama Stack runs on OpenShift. The MCP servers run as pods with OpenShift Routes, so Llama Stack can reach them.

If your instructor has already deployed MCP servers, skip to 4. Update .env and use the route URLs your instructor provided.
The MCP server container images must be built before deploying. If your instructor used the admin deploy script (00-setup/admin/deploy.sh), the images are already in the internal registry. If you need to build them yourself, see the Admin Guide: Building Images Manually.
Deploy into the same namespace as the backend APIs (e.g., acme-workshop). The MCP server images are stored in the internal registry under that namespace, and the env vars use cross-namespace DNS to reach the APIs. 
oc project acme-workshop

1. Deploy Customer MCP

oc apply -f 02-mcp-servers/openshift/customer-mcp.yaml

2. Deploy Finance MCP

oc apply -f 02-mcp-servers/openshift/finance-mcp.yaml

3. Get the Route URLs

echo "CUSTOMER_MCP_SERVER_URL=https://$(oc get route mcp-customer-route -o jsonpath='{.spec.host}')/mcp"
echo "FINANCE_MCP_SERVER_URL=https://$(oc get route mcp-finance-route -o jsonpath='{.spec.host}')/mcp"

4. Update .env

Set the MCP server URLs in your .env file to the route URLs from the previous step (or from your instructor):

CUSTOMER_MCP_SERVER_URL=https://mcp-customer-route-<namespace>.apps.<cluster>/mcp
FINANCE_MCP_SERVER_URL=https://mcp-finance-route-<namespace>.apps.<cluster>/mcp

5. Verify the Pods are Running

oc get pods -l app=customer-mcp
oc get pods -l app=finance-mcp

Both pods should show 1/1 Running.

Option B: Run MCP Servers Locally

Use this only if your Llama Stack also runs locally. A remote Llama Stack cannot reach localhost.

In two separate terminals, from the repo root:

python 02-mcp-servers/customer-mcp/customer-api-mcp-server.py
python 02-mcp-servers/finance-mcp/finance-api-mcp-server.py
Running from the repo root ensures load_dotenv() finds your .env file.

Your .env should have the localhost defaults:

CUSTOMER_MCP_SERVER_URL=http://localhost:9001/mcp
FINANCE_MCP_SERVER_URL=http://localhost:9002/mcp

Register with Llama Stack

Requires: Llama Stack server running (started in Module 00) and MCP servers deployed (Option A or B above).

Make sure your venv is activated (source .venv/bin/activate), then from the repo root:

python 02-mcp-servers/examples/1_register_customer_mcp.py
python 02-mcp-servers/examples/1_register_finance_mcp.py

Verify Registration

python 02-mcp-servers/examples/2_list_tools.py

You should see customer_mcp and finance_mcp toolgroups listed with their MCP endpoints.

Key Takeaways

  • MCP servers act as a bridge between LLMs and existing APIs

  • The @mcp.tool() decorator turns a Python function into an LLM-callable tool

  • Tools are registered with Llama Stack via client.toolgroups.register()

  • MCP uses HTTP transport (streamable HTTP) for communication

  • When Llama Stack is remote, MCP servers must also be deployed remotely (e.g., on OpenShift with routes)

= Llama Stack Server Setup (Admin Guide)
include::_attributes.adoc[]

Deploy a Llama Stack server with all capabilities the NovaCrest Agent Workshop requires.

== Prerequisites

* OpenShift cluster with *RHOAI operator* installed (includes the Llama Stack K8s operator)
* A *MaaS / vLLM inference endpoint* accessible from the cluster (provides models like `gpt-oss-120b`)

== Deploy on OpenShift (2 commands)

=== 1. Edit the distribution YAML

Set your MaaS token in `llamastack-distribution.yaml` (the MaaS URL is pre-configured):

[source,yaml]
----
- name: VLLM_API_URL
  value: "https://litellm-prod.apps.maas.redhatworkshops.io/v1"
- name: VLLM_API_TOKEN
  value: "your-api-token"   # <-- set your MaaS API key here
----

=== 2. Apply both files

[source,bash]
----
oc apply -f 00-setup/llama-stack-config/llamastack-configmap.yaml
oc apply -f 00-setup/llama-stack-config/llamastack-distribution.yaml
----

=== 3. Wait for the pod

[source,bash]
----
oc get pods -w -l llamastack.io/distribution=llamastack-novacrest-workshop
----

=== 4. Create a route and get the URL

[source,bash]
----
oc create route edge llamastack --service=llamastack-novacrest-workshop-service --port=8321
LLAMA_STACK_URL=https://$(oc get route llamastack -o jsonpath='{.spec.host}')
echo $LLAMA_STACK_URL
----

=== 5. Verify

[source,bash]
----
curl -s "$LLAMA_STACK_URL/v1/models" | python3 -m json.tool
----

=== 6. Set the URL in `.env`

[source,text]
----
LLAMA_STACK_BASE_URL=https://llamastack-....apps.your-cluster.com
----

That's it. The Llama Stack pod connects to your MaaS endpoint for LLM inference and runs embedding, vector store, agents, safety, eval, and tool runtime inline.

== Verify All Capabilities

From the repo root, run the readiness check:

[source,bash]
----
python 00-setup/verify_llama_stack.py
----

All 6 checks should pass before starting the workshop. See xref:00-setup.adoc#_deep_verification_optional[Deep Verification] for sample output.

== Alternative: Run Locally

If you don't have OpenShift, you can run Llama Stack locally using the standalone `run.yaml`:

[source,bash]
----
export VLLM_API_URL=https://your-vllm-endpoint/v1
export VLLM_API_TOKEN=your-token
pip install llama-stack
llama stack run 00-setup/llama-stack-config/run.yaml
----

Or use the simplest path with Ollama:

[source,bash]
----
uv run --with llama-stack llama stack run starter --image-type venv
----

Then set `LLAMA_STACK_BASE_URL=http://localhost:{llama-stack-port}` in your `.env`.

== Deploy Backend Services (Instructor-Led Workshop)

For an instructor-led workshop, you also need to deploy the NovaCrest backend APIs, PostgreSQL databases, and MCP servers so that participants use remote services instead of running them locally.

Helm charts are provided in `site/13-deployment/helm/`:

=== Backend APIs + PostgreSQL

[source,bash]
----
helm install novacrest-app site/13-deployment/helm/novacrest-app/
----

This deploys:

* *Customer API* -- Spring Boot app with PostgreSQL (`novacrest_customer` database)
* *Finance API* -- Spring Boot app with PostgreSQL (`novacrest_finance` database)
* OpenShift Routes for external access

=== MCP Servers

[source,bash]
----
helm install novacrest-mcp site/13-deployment/helm/novacrest-mcp/
----

This deploys:

* *Customer MCP* -- wraps the Customer API (connects via internal cluster DNS `http://novacrest-customer-service:8081`)
* *Finance MCP* -- wraps the Finance API (connects via internal cluster DNS `http://novacrest-finance-service:8082`)
* OpenShift Routes for external access

NOTE: The Helm values wire MCP servers to backend APIs using *in-cluster service names*, so MCP-to-API traffic stays inside the cluster. Only the MCP routes are exposed externally.

=== Collect URLs for Participants

After all services are deployed, gather the route URLs to share with workshop participants:

[source,bash]
----
echo "LLAMA_STACK_BASE_URL=https://$(oc get route llamastack -o jsonpath='{.spec.host}')"
echo "CUSTOMER_API_BASE_URL=https://$(oc get route novacrest-customer-service -o jsonpath='{.spec.host}')"
echo "FINANCE_API_BASE_URL=https://$(oc get route novacrest-finance-service -o jsonpath='{.spec.host}')"
echo "CUSTOMER_MCP_SERVER_URL=https://$(oc get route mcp-customer-route -o jsonpath='{.spec.host}')/mcp"
echo "FINANCE_MCP_SERVER_URL=https://$(oc get route mcp-finance-route -o jsonpath='{.spec.host}')/mcp"
----

Participants paste these values into their `.env` file (uncomment the "Remote" lines in `.env.example` and replace the placeholders).

== Troubleshooting

[cols="2,4", options="header"]
|===
|Problem
|Solution

|Pod in CrashLoopBackOff
|Check logs: `oc logs -l llamastack.io/distribution=llamastack-novacrest-workshop`. Usually a bad `VLLM_API_URL` or token.

|Models list empty
|The vLLM provider auto-discovers models. Verify your MaaS has models: `curl -H "Authorization: Bearer $TOKEN" $VLLM_API_URL/models`

|Embedding model missing
|The `sentence-transformers` provider downloads on first use. Pod needs internet access; startup takes 1-2 min.

|Route returns 503
|Pod still starting. Wait for `1/1 Running` in `oc get pods`.
|===

= Llama Stack Server Setup (Admin Guide)
include::_attributes.adoc[]

Deploy a Llama Stack server with all capabilities the ACME Agent Workshop requires.

== Prerequisites

* OpenShift cluster with *RHOAI operator* installed (includes the Llama Stack K8s operator)
* A *MaaS / vLLM inference endpoint* accessible from the cluster (provides models like `gpt-oss-120b`)

== Deploy on OpenShift (2 commands)

=== 1. Edit the distribution YAML

Set your MaaS token in `llamastack-distribution.yaml` (the MaaS URL is pre-configured):

[source,yaml]
----
- name: VLLM_API_URL
  value: "https://litellm-prod.apps.maas.redhatworkshops.io/v1"
- name: VLLM_API_TOKEN
  value: "your-api-token"   # <-- set your MaaS API key here
----

=== 2. Apply both files

[source,bash]
----
oc apply -f 00-setup/llama-stack-config/llamastack-configmap.yaml
oc apply -f 00-setup/llama-stack-config/llamastack-distribution.yaml
----

=== 3. Wait for the pod

[source,bash]
----
oc get pods -w -l llamastack.io/distribution=llamastack-acme-workshop
----

=== 4. Create a route and get the URL

[source,bash]
----
oc create route edge llamastack --service=llamastack-acme-workshop-service --port=8321
LLAMA_STACK_URL=https://$(oc get route llamastack -o jsonpath='{.spec.host}')
echo $LLAMA_STACK_URL
----

=== 5. Verify

[source,bash]
----
curl -s "$LLAMA_STACK_URL/v1/models" | python3 -m json.tool
----

=== 6. Set the URL in `.env`

[source,text]
----
LLAMA_STACK_BASE_URL=https://llamastack-....apps.your-cluster.com
----

That's it. The Llama Stack pod connects to your MaaS endpoint for LLM inference and runs embedding, vector store, agents, safety, eval, and tool runtime inline.

== Verify All Capabilities

From the repo root, run the readiness check:

[source,bash]
----
python 00-setup/verify_llama_stack.py
----

All 6 checks should pass before starting the workshop. See xref:00-setup.adoc#_deep_verification_optional[Deep Verification] for sample output.

== Deploy Backend Services (Instructor-Led Workshop)

For an instructor-led workshop, you also need to deploy the ACME backend APIs, PostgreSQL databases, and MCP servers so that participants use remote services instead of running them locally.

=== Option A: Automated Deploy Script (Recommended)

A single script builds all container images using OpenShift Binary Builds (no external registry needed) and deploys everything:

[source,bash]
----
cd agent-workshop
bash 00-setup/admin/deploy.sh acme-workshop
----

This will:

. Build 6 container images via `oc new-build --binary`:
  * 3 Java Spring Boot APIs (Customer, Finance, Mortgage)
  * 3 Python MCP servers (Customer, Finance, Mortgage)
. Deploy 3 PostgreSQL instances
. Deploy all 6 services with OpenShift Routes
. Print the `.env` block with all URLs ready for participants

The full process takes approximately 15-20 minutes (Java builds take 2-4 minutes each).

To tear down all resources later:

[source,bash]
----
bash 00-setup/admin/teardown.sh acme-workshop
----

=== Option B: Helm Charts

Helm charts are also available in `site/13-deployment/helm/`. Images must be built first (see step 1 from Option A or build manually with `oc new-build`).

[source,bash]
----
helm install acme-app site/13-deployment/helm/acme-app/
helm install acme-mcp site/13-deployment/helm/acme-mcp/
----

NOTE: The Helm charts currently cover Customer and Finance only. For the full workshop including the Mortgage capstone, use the deploy script (Option A) or deploy the mortgage services separately using `mortgage-use-case/openshift/mortgage-mcp.yaml`.

=== Building Images Manually

If you need to build images individually (for example, to update a single service):

[source,bash]
----
# MCP server example (Python)
oc new-build --binary --strategy=docker --name=customer-mcp -n acme-workshop
oc start-build customer-mcp --from-dir=02-mcp-servers/customer-mcp/ --follow -n acme-workshop

# API example (Java -- uses multi-stage Dockerfile under deployment/)
oc new-build --binary --strategy=docker --name=customer-api -n acme-workshop
oc start-build customer-api --from-dir=01-backend-apis/customer-api/ --follow -n acme-workshop
----

Each service has a `Dockerfile` in its directory:

* APIs: `01-backend-apis/<name>/deployment/Dockerfile` and `mortgage-use-case/mortgage-api/deployment/Dockerfile`
* MCP servers: `02-mcp-servers/<name>/Dockerfile` and `mortgage-use-case/mortgage-mcp/Dockerfile`

=== Collect URLs for Participants

After all services are deployed (via deploy script, Helm, or manual), gather the route URLs:

[source,bash]
----
echo "LLAMA_STACK_BASE_URL=https://$(oc get route llamastack -n llamastack -o jsonpath='{.spec.host}')"
echo "CUSTOMER_API_BASE_URL=https://$(oc get route acme-customer-service -o jsonpath='{.spec.host}')"
echo "FINANCE_API_BASE_URL=https://$(oc get route acme-finance-service -o jsonpath='{.spec.host}')"
echo "MORTGAGE_API_BASE_URL=https://$(oc get route mortgage-api-route -o jsonpath='{.spec.host}')"
echo "CUSTOMER_MCP_SERVER_URL=https://$(oc get route mcp-customer-route -o jsonpath='{.spec.host}')/mcp"
echo "FINANCE_MCP_SERVER_URL=https://$(oc get route mcp-finance-route -o jsonpath='{.spec.host}')/mcp"
echo "MORTGAGE_MCP_SERVER_URL=https://$(oc get route mcp-mortgage-route -o jsonpath='{.spec.host}')/mcp"
----

Participants paste these values into their `.env` file (uncomment the "Remote" lines in `.env.example` and replace the placeholders).

== Troubleshooting

[cols="2,4", options="header"]
|===
|Problem
|Solution

|Pod in CrashLoopBackOff
|Check logs: `oc logs -l llamastack.io/distribution=llamastack-acme-workshop`. Usually a bad `VLLM_API_URL` or token.

|Models list empty
|The vLLM provider auto-discovers models. Verify your MaaS has models: `curl -H "Authorization: Bearer $TOKEN" $VLLM_API_URL/models`

|Embedding model missing
|If using `sentence-transformers`: pod needs internet access, downloads on first use (~1-2 min). If using `vllm-embedding`: verify the vLLM embedding endpoint is accessible and supports the `dimensions` parameter (may need `--hf-overrides` for matryoshka models).

|Route returns 503
|Pod still starting. Wait for `1/1 Running` in `oc get pods`.
|===

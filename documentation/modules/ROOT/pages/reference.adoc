== Key Concepts

[cols="2,4,2", options="header"]
|===
|Concept
|What It Is
|Where You Learn It

|*Llama Stack*
|Open-source, community-driven platform providing a unified API for inference, agents, tools, RAG, safety, and evals -- a run-anywhere contract for AI agents
|xref:03-llama-stack-basics.adoc[Module 03]

|*MCP* (Model Context Protocol)
|Open protocol for exposing backend APIs as tools that LLMs can call autonomously
|xref:02-mcp-servers.adoc[Module 02]

|*FastMCP*
|Python library for building MCP servers with minimal boilerplate
|xref:02-mcp-servers.adoc[Module 02]

|*Agent*
|An LLM with tools, instructions, and session management that can reason and act
|xref:04-agents-with-tools.adoc[Modules 03-05]

|*RAG*
|Retrieval-Augmented Generation -- augmenting LLM responses with relevant documents
|xref:08-rag.adoc[Module 08]

|*Safety Shields*
|Content classifiers (TrustyAI Guardrails for PII detection, or Llama Guard for broader classification) that check inputs and outputs
|xref:09-safety-shields.adoc[Module 09]

|*LLM-as-Judge*
|Using a separate LLM to evaluate response quality
|xref:10-evaluations.adoc[Module 10]
|===

== Script Numbering

Scripts in the core learning path (Modules 03-05) use a *global numbering scheme* that runs continuously across modules:

[cols="1,2,3", options="header"]
|===
|Scripts
|Module
|Topic

|`1_*`
|03-llama-stack-basics
|Hello world, streaming, tool listing

|`4_*` - `5_*`
|04-agents-with-tools
|Single and multi-domain agents

|`6_*` - `7_*`
|05-multi-turn-and-hitl
|Multi-turn conversations, HITL
|===

Other modules (08, 09, 10, mortgage-use-case) use *module-local numbering* starting at `0_` or `1_`.

== Environment Variables

All modules share a single `.env` file at the repo root. Copy `.env.example` to `.env` and update values for your deployment scenario. See {github-repo}/blob/main/.env.example[.env.example,window=_blank] for the full annotated template.

TIP: In an *instructor-led workshop*, your instructor provides the remote URLs for Llama Stack, APIs, and MCP servers. Uncomment the "Remote" lines in `.env.example` and replace the placeholder URLs.

== Troubleshooting

[cols="2,3", options="header"]
|===
|Problem
|Solution

|`RuntimeError: No response available`
|Your Llama Stack is remote but MCP servers are on `localhost`. Remote Llama Stack cannot reach your local machine. Deploy MCP remotely or run Llama Stack locally. See xref:00-setup.adoc#_deployment_scenarios[Deployment Scenarios].

|`Connection refused` on Llama Stack
|Verify the server is running: `curl $LLAMA_STACK_BASE_URL/v1/models`

|`LLAMA_STACK_BASE_URL not set`
|Copy `.env.example` to `.env` and set `LLAMA_STACK_BASE_URL` to your server URL (local or remote)

|Empty tool lists
|Ensure MCP servers are running on their expected ports. If Llama Stack is remote, MCP servers must also be deployed remotely -- `localhost` MCP URLs are not reachable from a remote server.

|MCP tools fail with remote Llama Stack
|MCP server URLs must be reachable *from the Llama Stack server*, not just from your laptop. Deploy MCP servers on the same cluster or expose them via public routes.

|Model not found
|Check `INFERENCE_MODEL` matches a model on your Llama Stack server (`curl $LLAMA_STACK_BASE_URL/v1/models`)

|`429 Too Many Requests` or rate limiting
|The MaaS inference backend has rate limits. Wait 30-60 seconds and retry. For eval scripts, the built-in retry logic handles this automatically.

|Database errors
|Verify PostgreSQL is running and databases exist (`createdb acme_customer`)

|Import errors
|Activate your venv and run `pip install -r requirements.txt`
|===

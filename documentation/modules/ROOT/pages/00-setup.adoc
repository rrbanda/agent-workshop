= Module 00: Environment Setup
include::_attributes.adoc[]

== Learning Objectives

* Set up your Python environment and install dependencies
* Connect to a Llama Stack server
* Verify connectivity to all services

== Prerequisites

None -- this is the starting point.

== Concepts

*{llama-stack-repo}[Llama Stack,window=_blank]* is an open-source, community-driven platform that standardizes the building blocks for AI agents. It provides a single unified API for inference, agents, tools, RAG, safety, and evaluations -- instead of stitching together separate libraries, you get one SDK (`llama-stack-client`) that handles the full agent lifecycle. Think of it as the "Kubernetes for agents": a run-anywhere contract with a plugin architecture that lets you swap model providers, vector databases, and runtimes without changing your agent code. In this workshop, Llama Stack is the backbone -- every module from 03 onward uses it.

NOTE: *No local PostgreSQL needed.* The backend APIs run on OpenShift with their own PostgreSQL instances. You do not need to install or configure PostgreSQL locally.

NOTE: *Instructor-led workshops:* You only need *Python 3.12+*. Java, Maven, and PostgreSQL are only required if you are building and deploying the backend APIs yourself. All backend services, MCP servers, and Llama Stack are pre-deployed on OpenShift.

You also need access to a *Llama Stack server* with at least an inference model and an embedding model registered. The Llama Stack server is pre-deployed on RHOAI (OpenShift AI) with all required models. Set `LLAMA_STACK_BASE_URL` in your `.env` to the server URL provided by your instructor or team.

TIP: *Admin reference:* The RHOAI deployment artifacts (ConfigMap, CRD, server config) are in the xref:llama-stack-admin.adoc[Llama Stack Admin Reference]. The Llama Stack server is already deployed and running.

NOTE: *Working directory:* All commands in this module run from the *repo root* (`agent-workshop/`).

== Step-by-Step Setup

=== 1. Python Environment

[source,bash]
----
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
----

IMPORTANT: *Do not skip `pip install`.* The root `requirements.txt` installs all Python dependencies for the entire workshop, including `llama-stack-client`, `fastmcp`, `httpx`, and `python-dotenv`. If you skip this step, later modules will fail with `ModuleNotFoundError`.

Verify the key packages are installed:

[source,bash]
----
python -c "import llama_stack_client; print('llama-stack-client', llama_stack_client.__version__)"
python -c "import fastmcp; print('fastmcp OK')"
----

=== 2. Log In to OpenShift

Use the cluster URL and credentials you were provided:

[source,bash]
----
oc login <cluster-api-url> --username=<your-username> --password=<your-password>
----

Or, if you were given a token (from the OpenShift web console under your username > "Copy login command"):

[source,bash]
----
oc login --token=<your-token> --server=<cluster-api-url>
----

Verify you are logged in:

[source,bash]
----
oc whoami
oc project
----

=== 3. Environment Variables

[source,bash]
----
cp .env.example .env
# Edit .env -- set LLAMA_STACK_BASE_URL and verify model names match your server
----

The `.env.example` defaults to `{inference-model}` for inference and `{embedding-model}` for embedding. Update these if your Llama Stack server uses different model identifiers.

IMPORTANT: *MCP servers must be deployed on OpenShift.* Since Llama Stack runs on RHOAI, MCP server URLs must be reachable from the cluster. === 4. Verify Llama Stack Server

[source,bash]
----
curl $(grep LLAMA_STACK_BASE_URL .env | cut -d= -f2)/v1/models
----

You should see at least an inference model (e.g., `{inference-model}`) and an embedding model (e.g., `{embedding-model}`) in the response.

IMPORTANT: *MCP connectivity:* The Llama Stack server must be able to reach your MCP servers over the network. Since Llama Stack runs on RHOAI, MCP servers must also be deployed on OpenShift with routes (see xref:02-mcp-servers.adoc[Module 02]).

=== 5. PostgreSQL Databases (Self-Deploy Only)

IMPORTANT: *Skip this step if you are using pre-deployed APIs on OpenShift* (instructor-led). PostgreSQL runs on the cluster and is already configured. This section is only needed if you are building and deploying APIs yourself.

Ensure PostgreSQL is running before creating the databases. You can check with `pg_isready`.

The backend APIs connect as user `postgres` with password `postgres`. On *macOS* this usually works out of the box. On *Linux* (Fedora, RHEL, Ubuntu), you may need to configure PostgreSQL first:

[source,bash]
----
# Linux only: set the postgres user password (the Spring Boot APIs expect 'postgres'/'postgres')
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'postgres';"
----

If you get authentication errors when starting the APIs (Module 01), check your `pg_hba.conf` (typically at `/var/lib/pgsql/data/pg_hba.conf` on Fedora or `/etc/postgresql/*/main/pg_hba.conf` on Ubuntu). Ensure local connections use `md5` or `trust`:

[source,text]
----
# TYPE  DATABASE  USER  ADDRESS      METHOD
local   all       all                md5
host    all       all   127.0.0.1/32 md5
----

After editing, restart PostgreSQL: `sudo systemctl restart postgresql`.

Now create the databases:

[source,bash]
----
createdb acme_customer
createdb acme_finance
createdb acme_mortgage    # needed for the capstone
----

== Verification

[source,bash]
----
# Check Llama Stack
curl $(grep LLAMA_STACK_BASE_URL .env | cut -d= -f2)/v1/models

# Check Python
python --version  # Should be 3.12+

# Check OpenShift
oc whoami         # Should print your username
----

If building backend APIs locally before deploying, also verify:

[source,bash]
----
java --version    # Should be 21+
mvn --version     # Should be 3.8+
----

=== Deep Verification (Optional)

The basic `curl` check confirms the server is reachable. For a thorough check of all capabilities the workshop uses (chat, embedding, vector stores, safety, tool runtime), run:

[source,bash]

----

This tests six capabilities and reports PASS/FAIL for each. All checks should pass before proceeding. Example output:
